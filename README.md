# Design Tests

A Codex skill for choosing tests that distinguish correct behavior from plausible mistakes. Combines requirements discovery, lightweight BDD, TDD, boundary/state testing, independent oracles, and honest execution evidence. No mandatory framework or dependency.

**Первая версия, 26 октября 2026.** Скилл — на английском, исследование и карточка интервью — на русском. Агент отвечает на языке пользователя.

## Установка в Codex

Попроси Codex:

```text
Используй $skill-installer и установи скилл из
https://github.com/VileBody/agentic-testing-skill/tree/main/skills/design-tests
```

Будет установлена только папка `skills/design-tests`, включая её references. Исследование и evals для работы скилла не нужны. После установки скилл доступен со следующего сообщения. Если версия уже установлена, сначала сравни изменения; установщик не перезаписывает существующую папку молча.

## Вызов на интервью

```text
$design-tests
У нас 45 минут. Для задачи ниже выясни существенные правила,
выбери тесты против самых важных ошибок, затем реализуй решение
и покажи реальные результаты проверок. Держи setup небольшим.

<условие задачи>
```

Для этапа планирования:

```text
$design-tests
Пока только спроектируй проверки: правило → возможная ошибка →
различающий пример → ожидаемый результат и его основание.
Отдельно отметь бизнес-вопросы, без ответа на которые нельзя выбрать expected.
```

Для проверки существующих тестов:

```text
$design-tests
Найди существенные дефекты, которые нынешние тесты могут пропустить.
Предложи или выполни подходящие проверки в рамках этой задачи.
```

## Как устроен скилл

[SKILL.md](skills/design-tests/SKILL.md) содержит примерно 750 английских слов. Он направляет агента от требований к рискам, различающим примерам и наблюдаемому результату запуска. Подробности загружаются по необходимости:

- [BDD и выбор случаев](skills/design-tests/references/bdd-and-test-design.md)
- [Качество тестов и mutation probes](skills/design-tests/references/test-quality.md)
- [Data/ML](skills/design-tests/references/data-ml.md)
- [API и состояние](skills/design-tests/references/stateful-api.md)
- [UI](skills/design-tests/references/ui.md)
- [Интервью](skills/design-tests/references/interviews.md)

Gherkin, property-based framework, mutation testing и отдельный reviewer выбираются по пользе для задачи. Автоматический выбор скилла разрешён стандартными настройками Codex; явный вызов удобен на интервью. Другие агенты могут читать Markdown, но их установка и поведение здесь не проверены.

## Что проверено

В одном парном прогоне на задаче агрегации событий оба набора — со скиллом и без него — приняли две корректные реализации и обнаружили 17 из 17 внесённых дефектов. Для каждого набора 15 дефектов дали assertion failures; ещё 2 вызвали недопустимые ошибки на валидных данных и были разобраны вручную. Отдельный прогон с исправлением опечатки не добавил тестов или зависимостей.

Это проверка работоспособности первой версии, **не доказательство преимущества скилла**. Повторные trials, затраты времени/токенов, неявный выбор и все доменные профили ещё не оценены. [Результаты и воспроизведение](evals/README.md).
